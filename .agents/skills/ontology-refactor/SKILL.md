# Ontology Refactor

Seguir estas etapas na ordem indicada para toda alteração de classes em
`core/energy-domain-ontology.ttl`. Não pular etapas.

## 1. Analisar o impacto (somente leitura)

Antes de modificar qualquer arquivo:

1. Localizar a definição e todas as ocorrências da classe-alvo com `rg -n`.
2. Localizar subclasses diretas com uma busca por
   `rdfs:subClassOf edo:TargetClass`.
3. Repetir a busca para cada subclasse encontrada até mapear todas as
   subclasses indiretas.
4. Inspecionar o bloco completo de cada classe envolvida para identificar a
   superclasse e referências como `hasAttribute`, `hasDiscipline`,
   `ifc_equivalentClass` e propriedades relacionadas.
5. Identificar classes ou referências que ficariam órfãs após uma remoção ou
   reparentalização.
6. Para criação, confirmar que o identificador da nova classe ainda não existe.

Usar buscas equivalentes a:

```bash
rg -n 'edo:TargetClass\b|#TargetClass\b' core/energy-domain-ontology.ttl
rg -n 'rdfs:subClassOf\s+edo:TargetClass\b' core/energy-domain-ontology.ttl
```

Preservar quaisquer alterações preexistentes do usuário. Consultar `git diff`
para distinguir o estado anterior das alterações solicitadas na sessão.

## 2. Apresentar o plano

Apresentar ao usuário, sem editar arquivos:

- entidades a criar, alterar ou excluir, com números de linha quando existirem;
- hierarquia antes e depois em árvore ASCII;
- referências e atributos afetados;
- riscos de referências órfãs, subclasses sem pai e ordenação.

Não executar o plano na mesma mensagem em que ele for apresentado. Aguardar uma
mensagem posterior do usuário autorizando explicitamente a implementação.

## 3. Definir a documentação

Antes da execução, perguntar em qual arquivo registrar o changelog, por exemplo
`docs/changelog/flexible-v2.1.md`.

- Se o arquivo existir, planejar o acréscimo ao final.
- Se não existir, planejar sua criação.
- Não escrever o changelog antes da autorização explícita da etapa anterior.

Usar os seguintes formatos no changelog.

### Classe criada

```turtle
###  https://w3id.org/energy-domain/edo#NewClass
edo:NewClass rdf:type owl:Class ;
               rdfs:subClassOf edo:ParentClass ;
               dcterms:identifier "NewClass" ;
               skos:definition "..."@en ;
               skos:prefLabel "..."@en .
```

### Superclasse alterada

```diff
- rdfs:subClassOf edo:OldClass ;
+ rdfs:subClassOf edo:NewClass ;
```

### Disciplina adicionada

```diff
+ edo:hasDiscipline edo:SubseaFlexiblePipesEngineering ;
```

### Atributos removidos ou adicionados

```diff
- edo:hasAttribute edo:OldAttribute ;
+ edo:hasAttribute edo:NewAttribute ;
```

### Classe removida

```turtle
###  https://w3id.org/energy-domain/edo#RemovedClass
edo:RemovedClass rdf:type owl:Class ;
                  rdfs:subClassOf ... ;
                  skos:definition "..."@en ;
                  skos:prefLabel "..."@en .
```

## 4. Executar somente após autorização

Após receber uma mensagem posterior autorizando explicitamente a execução:

1. Aplicar mudanças pequenas e localizadas com `apply_patch`, usando contexto
   exato para não atingir blocos semelhantes.
2. Inserir toda nova classe no final do arquivo, imediatamente antes de
   `### Generated by the OWL API`.
3. Reler com `sed` ou `rg` cada região alterada após cada patch.
4. Atualizar o changelog definido na etapa 3 na mesma execução.
5. Não corrigir nem sobrescrever alterações manuais fora do escopo da tarefa.

## 5. Validar depois da modificação

Executar, no mínimo:

```bash
rg -c 'owl:Class' core/energy-domain-ontology.ttl
rg -n 'rdfs:subClassOf\s+edo:TargetClass\b' core/energy-domain-ontology.ttl
```

Verificar:

- classe criada, alterada ou excluída conforme o plano;
- ausência de referências órfãs a classes excluídas;
- subclasses reparentalizadas corretamente;
- atributos e disciplinas movidos corretamente, quando aplicável;
- changelog atualizado;
- diff final limitado ao escopo autorizado.

## 6. Preparar a mensagem de commit

Propor uma mensagem no formato `feat(core): <ação resumida>`, por exemplo:

- `feat(core): create NewClass, remove OldClass, reparent ChildClass`
- `feat(core): add SubseaFlexiblePipesEngineering discipline to ClassName`
- `feat(core): remove ParentClass, reparent ChildClass to GrandparentClass`
- `feat(core): move attributes from SourceClass to TargetClass`

Não criar o commit salvo se o usuário não o solicitar explicitamente.
